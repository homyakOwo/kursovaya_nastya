# Корпоративный Telegram-бот для управления задачами

**Учебный проект для курсовой «Автоматизация управления корпоративными задачами с использованием ботов в мессенджерах».**

Это самостоятельный проект. Использует Python 3.11+, Telegram Bot API через `aiogram 3` и локальную БД SQLite. Не подключён к чужим корпоративным данным. Код опубликован без рабочего токена; для реальной работы необходим свой токен от @BotFather.

## Функциональные возможности

- Регистрация участников по заранее заданному списку Telegram ID.
- Руководитель создаёт задачи, назначает/меняет исполнителей, просматривает общий отчёт и запускает напоминания командой `/remind`.
- Исполнитель просматривает свои задачи, меняет статус на «В работе» / «Готово» и видит журнал своей задачи.
- Сроки хранятся в формате `ГГГГ-ММ-ДД`.
- История изменений фиксируется в таблице `history`.
- SQLite хранит данные между перезапусками, а параметризованные запросы защищают от простой SQL-инъекции.

## Быстрый запуск

1. Установите Python 3.11+; распакуйте архив целиком с папками.
2. Выполните `python -m pip install -r requirements.txt`.
3. Создайте нового Telegram-бота через [@BotFather](https://t.me/BotFather) и получите токен.
4. Узнайте собственный Telegram ID (в демонстрационных целях можно воспользоваться командой `/id`, но запустить защищённого бота нужно с заранее указанным ID администратора; узнать ID можно в настройках другого надёжного инструмента или Telegram API).
5. Задайте переменные окружения `BOT_TOKEN`, `ADMIN_IDS`, `ALLOWED_USER_IDS` и, при желании, `BOT_DB`. **Не публикуйте реальные значения в GitHub.** `.env.example` — лишь пример; программа не загружает `.env` автоматически.
6. Из корня проекта выполните `python -m taskbot` и напишите боту `/start` **в личном чате** от имени каждого разрешённого участника.

### Windows PowerShell

```powershell
$env:BOT_TOKEN="ВАШ_ТОКЕН"
$env:ADMIN_IDS="123456789"
$env:ALLOWED_USER_IDS="987654321,876543210"
python -m taskbot
```

### Linux / macOS

```bash
export BOT_TOKEN='ВАШ_ТОКЕН'
export ADMIN_IDS='123456789'
export ALLOWED_USER_IDS='987654321,876543210'
python -m taskbot
```

## Команды Telegram

| Команда | Доступ | Назначение |
| --- | --- | --- |
| `/start` | Разрешённый участник | Зарегистрироваться |
| `/help` | Все | Справка |
| `/id` | Все | Посмотреть Telegram ID |
| `/tasks` | Участник | Мои задачи |
| `/doing 1` | Исполнитель / руководитель | Перевести задачу №1 в работу |
| `/done 1` | Исполнитель / руководитель | Завершить задачу №1 |
| `/history 1` | Исполнитель / руководитель | История задачи |
| `/members` | Руководитель | Зарегистрированные участники |
| `/new 987654321 \| 2026-11-20 \| Подготовить отчёт` | Руководитель | Создать задачу |
| `/assign 1 987654321` | Руководитель | Переназначить исполнителя |
| `/all` | Руководитель | Все задачи |
| `/report` | Руководитель | Отчёт и нагрузка |
| `/remind` | Руководитель | Отправить напоминания о незавершённых задачах со сроком до двух дней, включая просроченные |

**Ограничение:** напоминания не отправляются сами по расписанию: их запускает администратор. Telegram может отклонить отправку сообщения пользователю, который не открыл личный чат с ботом. Успешная запись в БД не гарантирует доставку сообщения.

## Запуск тестов и локальной демонстрации

```bash
python -m unittest discover -s tests -v
python -m scripts.demo
```

Тесты проверяют бизнес-логику без доступа к Telegram и без реального токена. Демонстрация создаёт временную БД и выводит результаты в терминал.

## Безопасность и ограничения

- Не отправляйте в чат пароли, коммерческие тайны и персональные документы.
- Руководитель и участники определяются по Telegram ID из переменных окружения. Роли не редактируются через бота.
- Бот рассчитан на **одну учебную команду и частное общение**. Нет SSO, многокомандной модели, веб-панели, шифрования БД, резервного копирования и автоматического планировщика.
- Разграничение прав тестируется на уровне `TaskService`; интеграционные испытания с Telegram выполняются отдельно после настройки токена.
- Для промышленной эксплуатации потребуются аудит безопасности, управление секретами, доступность сервера и согласование с корпоративной политикой обработки данных.

## Публикация GitHub

Создайте **новый** репозиторий Насти, например `nastya-corporate-task-bot`, и загрузите *содержимое распакованной папки* с сохранением вложенных директорий `taskbot`, `tests`, `scripts`, `.github/workflows`. Не добавляйте `.env`, реальные токены, `.sqlite3` или `__pycache__`. После публикации проверьте вкладку **Actions**. Пока репозиторий не создан, готового URL и QR-кода на него нет.
